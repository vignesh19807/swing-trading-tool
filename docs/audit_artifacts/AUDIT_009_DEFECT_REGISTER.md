# AUDIT-009: Defect Register & Limitations Inventory

| ID | Severity | Component | Finding & Description | Evidence & Reproduction | Recommended Remediation | Classification |
|---|---|---|---|---|---|---|
| **DEF-001** | **Low** | Backend API (`/api/stocks/{symbol}`) | Route returns HTTP 200 with `status: INSUFFICIENT` instead of standard HTTP 404 when requested symbol is not in the universe | Probing `/api/stocks/INVALID_SYM_XYZ` returns HTTP 200 with `status: INSUFFICIENT` | Return HTTP 404 with structured error when symbol does not exist in `companies` table. | **Confirmed Defect (Documented)** |
| **DEF-002** | **Low** | Backend API (`/api/stocks/{symbol}/history`) | Parameter `timeframe` lacks strict enum validation and falls back to full history when an invalid string is passed | Probing `/api/stocks/TCS/history?timeframe=INVALID_TF` returns HTTP 200 with all 496 candles | Add FastAPI `Query` enum validation for `["1M", "3M", "6M", "1Y", "ALL"]`. | **Confirmed Defect (Documented)** |
| **DEF-003** | **Medium** | Database / Historical Data | In the production SQLite database, `quarterly_results` has `NULL` for `publication_date` across all 260 rows | `SELECT COUNT(*), COUNT(publication_date) FROM quarterly_results` yields `(260, 0)` | Ingest verified corporate filing announcement dates from NSE/BSE to supplement the 45-day statutory fallback lag. | **Accepted Historical Data Limitation** |
| **DEF-004** | **Informational** | Frontend Bundler | Ineffective dynamic import warning in Vite production build for `src/services/api.js` in `Sidebar.jsx` | `[INEFFECTIVE_DYNAMIC_IMPORT]` printed during `npm run build` | Convert dynamic import to top-level static import in `Sidebar.jsx`. | **Minor Optimization** |
| **DEF-005** | **Informational** | Test Documentation Discrepancy | Previous audit report loosely described "288 frontend tests", which represents the combined assertion count across 7 test suites rather than 288 individual test files | `node src/utils/run_all_tests.js` executes 7 suite files containing 288 passing assertions/tests | Clarify test reporting to distinguish suite files from test cases and individual assertions. | **Documentation Clarification** |
